# Phase 1 開発報告

実施日: 2026-11-11（日本時間）

## 構造分析

着手時は約57KBの `index.html` にCSS、60品のデータ、SVG画像生成、保存・献立・買い物・検索処理が混在していました。レシピ追加と画像差し替えが表示処理の変更を伴う構造で、自動テストはありませんでした。READMEと商用化ロードマップには収録数や画像に関する古い説明も残っていました。

栄養条件の絞り込み自体は既存実装に存在し、境界は400/600kcalと25/35gでした。条件不一致時に黙って条件を緩和しない既存動作を維持しました。使用されていない、条件を緩和する旧候補関数は削除しました。

## 実装内容

- 全60品を `data/recipes.json` に分離。既存のID・料理名・材料・数量・工程・調理時間・栄養数値は変更前と一致することを比較検証しました。
- HTML、CSS、画面処理、データ検証と絞り込み、画像表示を別ファイルに整理しました。フレームワーク変更・バックエンド導入は行っていません。
- 100品以上を同じ構造で扱えるようにし、画面の件数もデータから表示します。現在の収録数は60品です。
- 代表20品の実写風AI生成画像を制作・導入しました。[画像一覧](IMAGE_PREVIEW.md) で確認できます。既存SVGの料理イラストを、画像未準備40品については中立的なプレースホルダーに置き換えました。
- 正方形の640px / 320px WebP、レスポンシブ画像選択、遅延読み込み、画像の取得失敗時の代替表示を実装しました。詳細ダイアログでも画像を表示します。
- 640版は約40〜70KB、320版は約11〜19KB、全40ファイル合計1,406,530バイトです。生成元の大きなPNGは公開リポジトリには含めません。
- OpenAIの出力所有に関する規約を確認し、画像台帳に生成条件・原本名・SHA-256・確認記録・容量・権利の根拠を保存しました。第三者の料理写真は使用していません。
- 全画像にAI生成であることを表示し、暫定栄養値もカード上で明示しました。未知の脂質・炭水化物・食塩はJSONでnullとし、0として表示しません。
- データ取得失敗時は再読み込み案内を表示し、保存済みデータを保持します。localStorageの既存キーとIDを維持しました。

変更は `docs/meal-planner/` 内のみです。ABC分析アプリは変更していません。GitHub Pagesの静的配信を継続できます。

4. 主菜・副菜・汁物・主食の区分、ジャンル拡張、アレルギー・予算条件は次段階で設計します。
5. 実機テストと継続的な自動テスト実行を整備します。今回は対象ディレクトリ以外を変更しないためGitHub Actionsは追加していません。
