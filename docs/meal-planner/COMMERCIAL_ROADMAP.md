# 商用化ロードマップ（案）— ごはん計画

作成日: 2026-11-11

## 現在の状態
- GitHub Pages 公開の静的ブラウザアプリ
- 60料理の献立、人数設定、買い物リスト、端末内保存
- カロリーとたんぱく質による献立選択（仮の1人分概算値）
- 全60品のJSON管理、画像管理、データ・絞り込み・Chromium自動テスト
- 代表20品のAI生成による実写風画像、残り40品は画像準備中表示（制作方法・権利の記録はIMAGE_GUIDE.mdを参照）
- 生成AIによる新規献立生成、正確な栄養計算、ログイン、同期、課金は未実装

## Phase 0: 実用性と信頼性（0〜1か月）
- 本物の食品成分表・商品重量・調味料・油を用いて栄養計算を再設計し、出典と計算式を保持
- エネルギー/たんぱく質に加えて脂質・炭水化物・食塩相当量の計算
- 料理の追加・編集、主食・副菜・汁物の管理、原材料とアレルゲン表示
- 検索・集計・選択状態の自動テスト、複数ブラウザ・スマホ実機テスト
- レシピ・画像の権利台帳、プライバシーポリシー・免責文の整備

**受入基準例**: 50レシピ、栄養計算のサンプル監査、主要導線の自動テスト、画像ライセンス確認済み。

## Phase 1: MVP と顧客検証（1〜3か月）
- ターゲットを「一人暮らし / 高たんぱく・時短・作り置き志向」のように限定
- 食材の使い回し、予算上限、嫌いな食材、アレルギー設定
- 週次計画の編集、買い物リスト、作り置きの衛生目安
- 5〜20人に使ってもらい、利用頻度、献立決定時間、再訪率を記録
- AI機能はバックエンド側のみで呼び出し、JSONスキーマ検証後に表示
- AIが提案した栄養値は信用せず、材料マスタから計算

**受入基準例**: 週2回以上の利用者率、翌週の継続利用率、有料利用意向の確認。

## Phase 2: 商用ベータ（3〜6か月）
- GitHub Pages単体から、安全なホスティングとAPIサーバー、DBへ移行
- メールログイン、利用者別データ分離、パスワードレス認証、クラウド同期
- 決済代行、解約、返金、請求・サポート導線、監視・バックアップ
- 個人情報保護・利用規約・特商法表示、脆弱性診断、利用規約の弁護士レビュー
- AI利用の上限・レート制限・悪用防止・コスト監視

**受入基準例**: 課金から解約までの動線テスト、負荷テスト、退会時データ削除、監査ログ。

## Phase 3: 拡大（6〜12か月）
- 数百〜数千の監修レシピ、店舗/食材価格連携は提供条件のあるAPIから
- パーソナライズの品質測定、栄養監修、チーム運用、問い合わせ対応
- 有料プラン（例: 無料の週3日献立 / 有料の栄養最適化と使い切り計画）
- 正式な価格は継続率と推定顧客獲得費を見て決定

## 収益試算（保証ではない）
月額 480円で課金者 100人なら売上 48,000円/月、500人なら 240,000円/月。
ここから決済手数料、クラウド費、AI API、保守、税金などを差し引く。
重要KPI: 無料→有料転換率、翌月継続率、1ユーザー当たりAI原価、解約理由。

## 注意
- 栄養値は現状仮の概算であり、健康・医療判断に使用しない。
- 無許可の他社レシピ・料理写真を無断転載しない。
- 個人の健康情報やアレルギー情報はセンシティブになり得るため、目的・同意・保存期間・削除対応を明確化する。
- APIキーを静的WebページやGitHubに直書きしない。
- 「AI」を商用名に含める場合は、実際のAI機能が動作してからにする。
