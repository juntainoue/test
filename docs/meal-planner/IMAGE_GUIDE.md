# 料理画像の管理・制作

## 制作方針

代表20品から開始します。第三者の料理写真やブランド素材を転載せず、この開発セッションのOpenAI画像生成ツールで料理名と食材を指定して新規生成します。実写の料理撮影画像ではないため、画面に「AI生成の盛り付けイメージ」と表示します。

共通指定: 正方形、明るいアイボリーの卓上、白い陶器、左上からの柔らかい自然光、斜め上からの構図。主食を含むレシピ以外にご飯や副菜を勝手に追加しません。画像の食材量は栄養計算の根拠には使いません。

## 権利の根拠

2026-11-11確認: https://openai.com/policies/terms-of-use/ の「Ownership of content」に、適用法の範囲で利用者がOutputを所有し、OpenAIがOutputに対する権利を譲渡する旨が記載されています。商用利用の画像素材として、このセッションでオリジナル生成した出力を使用します。第三者の写真素材ライセンスを流用したものではありません。

生成物の独占性や著作権の成立を保証するものではありません。人物・ロゴ・商品パッケージは制作条件に含めず、食材と器のみを使用します。`data/image-manifest.json` に制作元・生成条件・原本識別子・確認記録を保管します。プレースホルダーSVGは本プロジェクト内で新規作成した図形です。

## 表示と容量

- 料理ごとに640×640と320×320のWebPを用意します。
- `srcset` / `sizes` によりブラウザが表示幅に合わせて選択します。
- `loading="lazy"` と `decoding="async"`、縦横サイズ固定で読み込みとレイアウトを安定させます。
- 同一ドメインから配信し、外部画像サイトへの接続はありません。
- 画像未準備・取得失敗時は共通の「料理画像は準備中」に切り替えます。
- 目安は640版150KB以下、320版60KB以下です。

## 追加方法

1. `recipes.json` の料理名と材料を基に画像を制作します。
2. 料理・主材料が一致し、不要な料理が入っておらず、文字やロゴがなく、カード表示に適することを目視確認します。
3. ImageMagick等で縦横比を保ったままWebPへ縮小・圧縮します。正方形の原本を使用し、料理の重要部分を切り取りません。

```sh
magick original.png -resize 640x640 -strip -quality 82 assets/images/recipe_id.webp
magick original.png -resize 320x320 -strip -quality 80 assets/images/recipe_id-320.webp
```

4. `image` の `src` と `srcSmall` に上記ファイルの相対パスを指定します。`alt` は料理の説明、`source` は制作元、`rights` は利用根拠、`reviewedAt` は確認日です。すべて確認後に `status: ready` とします。
5. マニフェストにも生成条件・権利の根拠・確認記録を追記します。
6. データ・画像の存在チェックとブラウザテストを実行し、実際のカード・詳細画面でも確認します。

残り40品は同じ手順で段階的に拡張します。料理を特定できない生成画像や別料理の使い回しは採用しません。
